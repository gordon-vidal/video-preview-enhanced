# Accessibility of the webviews (WCAG 2.1 AA pass)

Scope: the player page (`src/extension.js` `html()`, `media/player.js`, `media/player.css`), the
compare page (`src/compare.js` `compareHtml()`, `media/compare.js`, `media/compare.css`), and the
menus and overlays on top of them: simple / advanced modes and the Tools menu (`media/modes.js`),
the CC menu for subtitles and audio tracks (`media/tracks-menu.js`), scopes and codec x-ray
(`media/xray.js`). Checked in a real VS Code only (hidden runner), never in a browser.

## Fixes

- `aria-label` on every icon button (both pages); `canvas` is `role=img` "Video". Play / pause's
  label follows the state.
- `aria-pressed` on mute, loop, pip, modeBtn (player) and mute (compare), kept in step
  with the state; `aria-expanded` + `aria-controls` on compare's Compare button (2026-11-20: compare uses the
  player's bar and panels, docs/notes/compare-ui.md; the split divider is a `role=slider`, the tile menu `role=menu`).
- `aria-valuetext` on the seek bar: "0:01.234 of 0:10.000, frame 37" (player and compare).
- One polite live region `#live` (`role=status`, `aria-atomic`, `.sr-only`) per page; `toast()`,
  `showMessage()` and the pill (only when it turns ok / warn) go through `announce()`. The visible
  toast is `aria-hidden` so it is not read twice. `toast(text)`'s signature is unchanged, so main's
  `toast(text, ms = 900)` merges cleanly (the `announce(text)` call is the first line).
- Menus: roving focus (`tabIndex = -1` on items, arrows / Home / End move, Escape and Tab close and
  return focus to the menu button, running an item returns focus to the button). Sections are
  `role=group` labelled by their (now `aria-hidden`) heading; separators are `role=separator`;
  stepper buttons are menu items with names; tool hints become `aria-keyshortcuts`.
- `VpeModes.ownsKey(e)` (media/modes.js): text / number fields, list boxes, contenteditable, Space
  on checkbox / radio, and Space / Enter on a `:focus-visible` button or menu item belong to the
  control. Player, x-ray, compare and simple mode's tool-key filter skip those. A button clicked
  with the mouse is not `:focus-visible`, so Space there still plays and pauses (unchanged feel).
  Compare now loads `modes.js` for this.
- Focus ring: `:focus-visible` outline in `--vscode-focusBorder` for buttons, selects, inputs and
  `[tabindex]`; menu items get `--vscode-menu-selectionBorder` (HC). HC hover / on borders use
  `--vscode-contrastActiveBorder`.
- Contrast: `opacity` dimming replaced by `--vscode-descriptionForeground`; light-theme pill
  colours mixed towards the foreground; overlay text white (with its shadow) over the picture.
- `prefers-reduced-motion: reduce` turns the bar's transition off (both pages).
- `focusin` wakes the hidden bar in fullscreen; dismissing the notice with focus inside returns
  focus to Play.
- Compare Sync: opened from the keyboard, focus moves into the panel; Close / Escape return it to
  the Sync button.

## Tests

- `test/vscode/cases/ui.js` (real VS Code, debug probes `a11y` in player.js and `compare a11y` in

## 2026-11-20: the new bar and panels (docs/notes/ui-simple.md)

- Icon buttons with `aria-label` and `title` (with their key); mute `aria-pressed` and label Mute / Unmute; CC, ⓘ,
  speed and ⚙ have `aria-expanded` + `aria-controls="panel"`; the time is a button whose label is the position and frame.
- Panels are `role=dialog` with a label per page; rows are buttons (focus moves into the panel on open, ↑/↓/Home/End
  move it, Esc goes back to the main page or closes and returns focus to the bar button); Loop is `role=switch`;
  jump sizes, subtitles and audio tracks are `role=radiogroup` / `radio`; speed presets `aria-pressed`.
- The shortcuts sheet is a modal dialog (`aria-modal`), focus on Close, Tab stays, Esc / ? close it and return focus.
- Every keyboard path is checked in `case/ui`.

## Left to do

- Contrast was reasoned from the default Dark+, Light+ and HC themes' variables, not measured with
  a tool on every theme; custom themes can still pick poor `descriptionForeground` colours.
- The scopes, pixel readout and x-ray timeline are canvases: their content is visual only (no text
  alternative beyond the stats panel). The x-ray strip is not keyboard-explorable frame by frame
  (the `{` `}` keys move between keyframes instead).
- Subtitles drawn over the video are not mirrored to the live region (a screen reader user would
  usually turn them off anyway; could be an option).
- Compare's wipe divider is a `role=slider` already; its value text is a percentage, not checked
  with a screen reader.
- No real screen reader (NVDA / Narrator) session was run; the checks are on the accessibility
  attributes and focus, read through the test hook.
